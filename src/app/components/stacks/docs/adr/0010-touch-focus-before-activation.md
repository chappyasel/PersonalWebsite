# Establish selection before navigation

The first mobile tap on an Identity Prop will establish Touch Focus rather than immediately navigating or performing an explicit local action. It reveals a Portal Label when the prop has a destination or explicit local action, and gives movable-only props a persistent selected state without inventing a label. A subsequent tap on either an actionable focused prop or its now-actionable Portal Label follows the prop's semantic role through one shared activation path. The Portal Label appears adjacent to its prop and offset from the contact when space permits; otherwise it docks above the Peek Sheet with a short visual tether back to its owner. Touch Focus never expires on a timer; it clears when focus transfers or the visitor changes context through background touch, World travel, rail navigation, or Peek Sheet expansion. Touch visitors can therefore understand an outcome before committing and receive a dependable large target without forcing every object into identical behavior. Desktop destination props use the same selection state. Hover previews the label but never counts as selection. The first click pins the label, and a later click on the selected prop activates its destination. Clicking the visible label also activates it. Internal and external destinations follow the same rule. Desktop photos, book notes, close-ups, and small local actions keep their existing immediate response. Immersive actions opt into selection through `previewBeforeActivation`, including the Apple Vision Pro ride.

Carrying is not an activation tap. Normal release, browser cancellation, and unexpected pointer-capture loss all clear the carried prop's prior Touch Focus. The next quick tap establishes fresh focus and runs Focus Lean against the prop's current position. Only the following tap may activate it.

Selection lasts until the visitor dismisses it or changes context. Hovering another object does not replace or restart the selected label. Clicking another object transfers selection; empty-space clicks and Escape dismiss it. Escape also clears hover so the dismissed label does not immediately reopen. Labels stay beside their objects, with the existing mobile docking behavior. Camera Focus Lean runs after selection on both desktop and touch. Desktop pointer presses also use the existing object compression, which releases into the held selection response. Hover alone does not zoom the desktop camera.

The first 400 ms after selection cannot activate through another object click or tap, preventing rapid double gestures from skipping the preview. The visible label is an explicit action and remains directly usable. Drag release never activates, and desktop carrying clears prior selection. Scene pointer handlers ignore presses on DOM controls, including the selected label. The window pointer gesture alone owns desktop Portal activation; the later React Three Fiber click only stops propagation.

This change adds no Field Note. Selection fails achievement quality-bar test 2 because selecting an object is an interface step rather than a meaningful discovery. Existing discoveries still run on semantic activation, never on selection.

Portal Labels only use the object's projected position. If the object becomes hidden or its projection is temporarily unavailable, its label hides until projection returns. It never follows the cursor as a fallback. The action button inherits the glass surface's text color in both its resting and hover states.

Shelf labels show the destination or object title above a separate action line. The destination table owns route actions, including Weightlifting's "View site" and Systems' "Read article". Arbitrary site links default to "View site" and can supply a more specific action. "View site" is omitted when descriptive detail already appears below the title; specific actions remain visible. Labels allow up to 240 pixels, with a 280-pixel exception for the TJHSST medallion. Articles and music name their reading or listening action explicitly. Local actions keep their existing object title and verb. This copy change adds no discovery under quality-bar test 2 because it explains an existing interface action.
